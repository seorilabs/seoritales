# 이야기와 출간 판본 갱신

승인 근거: 사용자가 2026-11-10에 제시된 계획의 구현과 L1 검증, 웹 공개까지 지시했다. 기준은 원격 main b9c9483a3042d2689a44a6aeddf0c32550cc19cb다.

## 범위와 근거

기존 화면과 exporter를 유지하고 10번째 이야기의 원본 본문과 삽화, 교사용 안내를 추가한다. KDP 전체 제목 목록과 원본 제작 기록에 10권이 없으므로 전문을 공개하되 구매 페이지는 만들지 않는다. Bookshelf에서 Live와 ASIN이 확인된 8권 전자책과 9권 전자책·종이책을 반영한다. 1~9권의 각 판본도 대조한다. 가격과 재고는 추정하지 않고 기존 Attribution 링크를 보존한다. 원본 저장소의 미추적 작업은 수정하지 않으며 재현 가능한 exporter 및 상태 입력 패치를 남긴다.

## 인수조건과 검증

- 원본의 이야기, 그림, 원전명과 편집 질문이 홈, 이야기, 교사용 페이지와 검색 및 사이트맵에 연결된다.
- 전문·발췌와 판본별 링크, 구조화 데이터가 확인된 KDP 상태와 일치한다.
- `npm run check`, `npm run build`, `npm test`, `npm run lint`와 데스크톱·모바일 개발 브라우저 확인을 실행한다. 변경된 책 페이지와 공개 사이트의 본문, 이미지, 구매 링크, 사이트맵을 확인한다.
- 화면 재설계가 아니므로 L1 개발 환경에서 실행한다. 실제 기기는 사용하지 않는다. 한국어 Ready PR, 필수 검사와 중앙 배포 검증을 거쳐 공개한다. 실패 시 수정 PR로 복구한다.

기존 Pages workflow는 main push마다 배포해 중앙 검증 이전에 공개할 수 있다. 설계 선반영 PR에서 자동 공개를 중지하고 PR 정적 검사와 명시 dispatch 배포를 분리한다. dispatch는 동일 SHA의 개발 근거를 중앙 `before-deploy` 검증기로 확인한 뒤 빌드한다. 이 선반영 PR은 제품 콘텐츠를 배포하지 않는다. `actionlint`와 PR 정적 검사로 변경을 확인한다. 이후 콘텐츠 PR은 승인 설계 커밋이 조상이 되도록 새 main에서 만든다.
